- **לשמור את הרשימה** ב-`checkup_data/red_list.txt` (סימבול בשורה, שורה ראשונה `# ...` עם התאריך) — לגיבוי למסלול Yahoo.

- תאריך הבר האחרון (`t`) חייב להיות יום המסחר האחרון שנסגר, זהה לכל הטיקרים → זה ה-`bar_date`.
- `close` מה-batch חייב להיות שווה ל-close של הבר האחרון. אם לא (למשל הסקרינר כבר התחיל יום חדש) — להשתמש בערכי ה-OHLCV ולציין זאת למשתמש.

## שלב 4 — JSON
שמור כ-`checkup_data/data_YYYY-MM-DD.json` (תאריך הבקשה לפי שעון ישראל):

```json
{"date": "YYYY-MM-DD", "bar_date": "YYYY-MM-DD", "watchlist": "Red list", "tickers": {"NASDAQ:XXX": {
  "bars": [[o,h,l,c,v], ...12],
  "ATR": 0, "ADX": 0, "ADX1": 0, "DIp": 0, "DIm": 0, "CCI": 0, "CCI1": 0, "EMA20": 0, "EMA50": 0,
  "SMA150": 0, "RVOL": 0, "SMA20": 0, "BBU": 0, "SMA20W": 0, "BBUW": 0,
  "PP": 0, "R1": 0, "R2": 0, "S1": 0, "S2": 0,
  "H1M": 0, "L1M": 0, "H3M": 0, "L3M": 0, "vol10": 0,
  "news_level": "red|yellow|none", "news": "..."}}}
```
`news_level` / `news` אופציונליים — נוספים בשלב 5א.

מיפוי: `BBU` ← `BB.upper`, `SMA20W` ← `SMA20|1W`, `BBUW` ← `BB.upper|1W`, `ADX1` ← `ADX[1]`, `CCI/CCI1` ← `CCI20/CCI20[1]`, `RVOL` ← `relative_volume_10d_calc` (גיבוי בלבד), `vol10` ← `average_volume_10d_calc`, `DIp/DIm` ← `ADX+DI/ADX-DI`, `PP` ← `Pivot.M.Classic.Middle`.
דוגמה מלאה: `checkup_data/data_2026-10-26.json`

## שלב 4א — תמיכות, התנגדויות ותיקון (חובה, בשני המסלולים)
```bash
python3 yahoo_data.py levels checkup_data/data_YYYY-MM-DD.json
```
(במסלול Yahoo ה-`build` כבר עושה את זה.) מוסיף לכל מניה:
- **3 תמיכות מתחת לסגירה ו-3 התנגדויות מעליה, ביומי, לפי הסדר.** ההגדרה לפי המקובל (בדיקה ברשת 13/11/2026, המשתמש אישר):
  - רמה = Pivot: שיא/שפל שהוא הקיצון של 10 נרות מכל צד (כמו Pivots High Low בטריידינגוויו), ב-6 החודשים האחרונים.
  - Pivots במרחק עד 0.25 ATR = רמה אחת (אזור, רוחב עד 0.5 ATR).
  - נגיעה = נקודת מפנה קטנה (3 נרות מכל צד) בתוך האזור. **רמה צריכה לפחות 3 נגיעות.**
  - פחות מ-3 רמות בכיוון מסוים → להוסיף מהשנה האחרונה, מסומן `(שנה)`. אם עדיין חסר → `אין`.
  - עמודת **Pivot חודשי** (Traditional: S1 | P | R1) — נוסחה קבועה, נפרדת מהרמות.
- רמה שהיא גם שיא/שפל נדנדה **שבועי** (3 שבועות מכל צד, 3 שנים, עד 0.15 ATR) מסומנת `★ שבועי` ובצבע כחול ב-xlsx. זו בקשה מפורשת של המשתמש.
- **תיקון:** תחילת התיקון = שיא 3 החודשים, שפל = הנמוך מאז, קו 50%, דיסקאונט/פרמיום. קירוב אוטומטי — אם התיקון התחיל לפני יותר מ-3 חודשים או שזה רק פולבק קטן, לומר זאת.

## שלב 5א — חדשות (חובה, לפני ה-Google Sheet)
הנרות לא רואים חדשות. מניה יכולה לקבל ציון גבוה ולהתרסק בפתיחה בגלל כותרת שיצאה בלילה או בפרה-מרקט (מקרה DASH, 5/11/2026: אמזון בחרה ב-Uber Eats כשותפה ו-DASH ירדה 13%. הכותרת הופיעה רק אצל AMZN ו-UBER, לא אצל DASH).
- **למי:** כל מניה בסטטוס ✅, 🔵 או 👁 אחרי שלב 5.
- **מה לבדוק:** `mcp-tv-get-news` (`limit=10`) **לטיקר עצמו וגם ל-2–3 המתחרות הישירות שלו** (לפי ידע כללי: DASH ← UBER, AMZN, CART; בנק ← בנקים דומים וכו'). בקבוצות של עד 7 קריאות.
- **אילו כותרות:** רק מאז סגירת הנר האחרון (16:00 ET של ה-`bar_date`) ועד עכשיו. כותרת מהותית שמצאת — לקרוא עם `mcp-tv-get-news-story` לפני שמסווגים.
- **סיווג** — לכתוב לכל מניה שנבדקה ב-JSON:
  - `"news_level": "red"` + `"news": "<משפט קצר + שעה ב-ET>"` — חדשות שעלולות להפיל את המניה: מתחרה שנכנס לתחום או עסקה של מתחרה, רגולציה/חסימת עסקה, הורדת תחזית, הנפקה/דילול, תביעה, פיטורי מנכ"ל, דוח לפני הפתיחה.
  - `"news_level": "yellow"` + `"news"` — חדשות שכדאי לדעת (שינוי המלצת אנליסט, עסקה קטנה, דוח בימים הקרובים).
  - `"news_level": "none"` — נבדק, אין חדשות מהותיות.
  - מניה שלא נבדקה — בלי השדות (העמודה תישאר ריקה).
- להריץ שוב את שלב 5 כדי שעמודת **חדשות** (עמודה 6) תיכנס לגיליון. ב-xlsx: ⚠ אדום, ℹ צהוב.
- **לא לשנות את הסטטוס או הציון** לפי החדשות — רק לסמן. ההחלטה של המשתמש.
- **אם ההרצה לפני 08:00 ET** (15:00 שעון ישראל): רוב חדשות הפרה-מרקט עוד לא יצאו — לומר זאת למשתמש ולהציע לבדוק שוב את המניות ב-✅ לפני הפתיחה.

## לוגיקה (`checkup.py`, משתמש בפונקציות של `ticker_report.py`)
מטרה: לתפוס **תחילת מהלך אחרי תיקון**, לא מגמה שכבר רצה. לכן אין RSI ואין ניקוד על מבנה EMA.
- **כיוון (30):** +DI > -DI = 15, ADX ≥ 20 = 10 (18-20 = 5), ADX עולה מאתמול = 5. כש-DI- מעל DI+ = 0
- **נר עם עוצמה (25):** מרובוזו ירוק היום 15 / ב-3 ימים האחרונים 10, ועוד דפוס הנר האחרון עד 10.
  מרובוזו = נר ירוק, גוף ≥ 85% מהטווח וגוף ≥ 0.5 ATR
- **ווליום (15):** ווליום היום האחרון חלקי ממוצע 10 הימים שלפניו (בלי היום עצמו), מחושב מהנרות. רק על נר ירוק: ≥1.5 = 15, ≥1.2 = 10, ≥1.0 = 4
- **CCI(20) (15):** חוצה למעלה את -100 או את 0 = 15, עולה מתחת ל-100 = 10, עולה מתחת ל-200 = 4
- **מעל SMA150 (10)**
- **סטטוס (עמודה 2, הגיליון ממוין לפיו ואז לפי הציון).** בולינגר = מיקום הסגירה ברצועה (SMA20 ±2σ) ביחידות σ, יומי ושבועי (עמודות 3–4):
  - ✅ **יש מקום:** טובה בשבועי וביומי (שתיהן עד +2σ), +DI > -DI, ADX ≥ 20
  - 🔵 **כמעט שם:** כמו ✅ אבל ADX מתחת ל-20 ועולה מאתמול
  - 👁 **מעקב:** טובה בשבועי, **מתוחה ביומי** (מעל +2σ). המשתמש משאיר אותה ב-Red list ובודקים שוב בכל הרצה עד שתבשיל
  - 🔴 **מתוחה בשבועי:** מעל +2σ בשבועי
  - ⛔ **לא לסחור:** ווליום ממוצע 10 ימים מתחת ל-500,000 מניות ביום (הסיבה והמספר בהערות), מחיר קפוא (ATR < 0.5% מהמחיר), מגמת ירידה (-DI > +DI עם ADX ≥ 20), או אין כיוון ללונג
  - **לא מתוח (5 נק' בציון):** בתוך רצועת בולינגר היומית
  - ב-xlsx כל סטטוס צבוע; ב-Google Sheet (CSV) רואים את האימוג'י והמיון
- **רמות לציון (פנימי, לא מוצג):** Pivot חודשי, שיא/שפל חודש ו-3 חודשים, EMA20/50, גבוה/נמוך 2 נרות אחרונים; משמשות לחישוב "יש מקום" בציון.
- **רמות בגיליון (עמודות 7–12):** תמיכה 1–3 / התנגדות 1–3 משלב 4א. אם השלב לא רץ — מוצגות הרמות הישנות בלי סימון שבועי.
